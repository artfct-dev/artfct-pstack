# Supported clients — install matrix

How to install a portable Agent Plugins v1 package (root `plugin.json` + `skills/` + `mcp.json`, e.g. the artfct plugin) per harness. Verified = live-tested by us; documented = per official docs, not yet run end to end. Version pinning is weak everywhere except git refs — always read back the installed `plugin.json` `version`.

| Client | Install | Skills surface | MCP | Notes |
|---|---|---|---|---|
| OMP | `~/.omp/agent/mcp.json` + `skills.customDirectories` → package dir; `/mcp reload` | `skill://<name>`, `/skill:<name>` | `type: http` + url (native shape); OAuth interactive | ✅ verified live |
| OpenClaw | `openclaw plugins install --force --accept-capabilities <path>` (`git:<owner/repo>@<ref>`, npm, ClawHub also work); `--profile` to isolate | plugin-bundled, auto | bundled MCP servers via plugin config | ✅ verified live, 14/14 skills |
| Hermes | Git installer needs **root manifest** (monorepo checkouts don't register); `hermes plugins validate <dir>` + `plugins doctor <dir>` pre-check; single skills by raw `SKILL.md` URL work | `artf─┴:…` namespaced — always qualify, unqualified names resolve to nothing | `mcp.json` streamable-http entries route to native remote client; OAuth interactive | ✅ verified live (skills in-agent, MCP wired, auth pending) |
| Claude Code / app / Cowork / Grok Build | repo ships `.claude-plugin/marketplace.json`: `/plugin marketplace add artfct-dev/artfct-pstack`, `/plugin install artfct-pstack@artfct-pstack` | `/artfct-pstack:<skill>`, auto + explicit | bundled incl. `.mcpb` + per-plugin Configure | ✅ verified live (CLI headless, 62 skills + 2 agents) |
| Codex CLI | `codex plugin marketplace add artfct-dev/artfct-pstack` + `codex plugin add artfct-pstack@artfct-pstack` (Codex reads the repo's `.claude-plugin/marketplace.json`; no wrapper needed) | `artfct-pstack:<skill>`, auto + slash | shares MCP config with desktop app + IDE on same host | ✅ verified live (headless, skills only — repo ships no `mcp.json`) |
| ChatGPT | Plugins catalog browse/install (desktop app); `Build skills` → distribute as bundled multi-skill plugins | shared ChatGPT↔Codex skill standard | shared MCP config across desktop/CLI/IDE | 🟡 INCONCLUSIVE — catalog install needs a signed-in GUI session (local ChatGPT.app here is the Codex desktop app); package fits the shared standard, bare repo accepted as Codex marketplace |
| VS Code | Agent Customizations → Plugins → `+` (marketplace, Git URL, local folder); deep-link `vscode://chat-plugin/install`; auto-discovers Copilot CLI installs under `~/.copilot/installed-plugins/` | Configure Skills, auto + `/` slash, namespaced per plugin | bundled servers appear in MCP list, per-server setup | 🟡 INCONCLUSIVE — app absent here; repo folder satisfies the local-folder shape (root `plugin.json` + 62 `SKILL.md`) |
| GitHub Copilot | `copilot plugin marketplace add OWNER/REPO\|URL\|/local-path`, `copilot plugin install PLUGIN@MARKETPLACE`; subdir + direct installs supported | plugin-bundled, all agent surfaces | plugin-bundled MCP (transports unverified) | ✅ verified live (headless, no auth, 62 skills, v0.1.0 read back; repo has no `.github/skills/`, skills load plugin-bundled) |
| Cursor | Marketplace one-click, `cursor agent --plugin-dir <dir>`, or copy skill folders into `.agents/skills/` / `.cursor/skills/` | auto-loaded, agent-decides + `/skill-name` | one-click marketplace installs | ✅ verified live (headless, 62 skills read back in-agent; benny stays dormant pending its merge step) |
| Devin | Marketplace, Add plugin → From repository (**owner/repo or git URL + subdir**), `.zip` upload, in-editor create; CLI `devin plugins install` | `/<plugin>:<skill>` or `@skills:<name>` | Customize → MCPs tab | 🟡 INCONCLUSIVE — CLI installs headless but plugin management needs `devin auth login` (account); package fits structurally, subdir installs supported |
| Kiro | **No package ingest — per-skill import only**: panel → Agent Steering & Skills → `+` → repo URL pointing at the skill **subdirectory** (not root) or local folder → `.kiro/skills/` | auto-match on description + `/name` | stdio + remote HTTP/SSE, OAuth for remote | 🟡 INCONCLUSIVE — app absent here; every skill is already at per-skill import granularity, simulated `.kiro/skills` placement reads back |
| NanoClaw | Manual copy of `skills/` content into host skill dirs (`.claude/skills/`, container `/app/skills`) | host-harness skills, `/add-<thing>` style | via container manifest + `mcp-remote` bridge | 🟡 INCONCLUSIVE — no NanoClaw host on this machine; all 62 skills pass `name`+`description` frontmatter |
| OpenHands | `/add-skill <GitHub-URL>` (skill-folder granularity) or `cp -r` into `.agents/skills/` / `~/.agents/skills/` | loads at conversation start | settings MCP config | 🟡 INCONCLUSIVE — conversation needs a real LLM key; CLI installs headless, skill fetch + `Skill.load` parse proven |
| Perplexity | Plugins page → Add custom → upload `.zip` (root `plugin.json`) or import public GitHub repo/folder URL | ≤32 skills per plugin, per-skill enable switch, `/` → Plugins | remote-only (`streamable-http\|http\|sse`, ≤15 servers, no stdio) | 🟡 INCONCLUSIVE — upload needs account + Computer plan + GUI; shape-check confirms artfct-pstack does NOT fit as-is (62 skills > 32 cap; files/size/MCP fine) |
| Antigravity | App: local skill dirs; CLI: `agy plugin install <name>\|<GitHub-URL>\|./local-path` | app + CLI skill dirs, auto + `/<skill>` | local + remote MCP (stdio/SSE/HTTP) | ✅ verified live (CLI `agy plugin install ./local-path`, 62 skills; `agents/` skipped by loader — OMP-tier frontmatter) |

Rules that hold everywhere: package root must contain `plugin.json` (monorepo subdirs need a client with subdir support — Devin and Copilot have it, Hermes does not); OAuth sign-in is always interactive; after installing, read back the installed `plugin.json` `version`.
